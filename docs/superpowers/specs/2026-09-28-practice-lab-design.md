# Practice lab — design

Sub-project 3 of 4 (Reading → Reliability → **Practice lab** → Interviewer). A new **Practice** nav item: live SQL and Python practice with built-in datasets and W3Schools/GeeksforGeeks-*style* lessons (original content; nothing copied from those sites).

## Constraints (user, 2026-09-28)

- Free, legal and secure.
- **Works fully offline.**
- **No new online services or accounts.**
- The app may grow in size to hold everything locally.
- The only security loosening approved is **WebAssembly**. No localhost/AI connections.
- Python libraries to bundle: **pandas, numpy, matplotlib, scikit-learn, seaborn, scipy** (the user accepted about 100–120 MB extra).

## Engine: Pyodide in a Web Worker

**Pyodide** is CPython compiled to WebAssembly, MPL-2.0, from the Pyodide project (originated at Mozilla). It runs in a dedicated **Web Worker**:
- **No Tauri IPC in the worker.** Workers don't receive `window.__TAURI_INTERNALS__`, so user code can't call the app's database, filesystem or any Tauri command. Verify at build time: `typeof self.__TAURI_INTERNALS__ === "undefined"` inside the worker.
- **Stop = `worker.terminate()`**, then a fresh worker. This kills infinite loops and recovers from crashes.
- **Network:** anything the worker fetches is still bound by the page CSP's `connect-src` (`'self'` plus Supabase). `micropip` installs from PyPI are impossible, and that's intended.

**SQL runs in the same worker through Python's standard `sqlite3`**, against an in-memory database seeded with the datasets on worker start. One engine, one sandbox, no extra SQL library. `pd.read_sql(query, conn)` works on the same tables, so lessons can mix SQL and pandas.

- **Lazy start:** the worker boots when Practice is first opened in a session, with a "Starting Python… (first time takes a few seconds)" state. Heavy packages load on first import (`pyodide.loadPackagesFromImports`), all from local files.

### Offline bundling

- A new `scripts/fetch-pyodide.mjs` is run once by the developer:
  - It downloads the pinned official Pyodide release archive (version and SHA-256 pinned in the script) from the project's GitHub releases.
  - It verifies the checksum.
  - It extracts the core runtime plus the wheels for the six packages **and their dependencies** into `apps/desktop/public/pyodide/`. The dependencies are resolved from the release's `pyodide-lock.json`.
- `apps/desktop/public/pyodide/` is **gitignored**, so large binaries never enter git. The build fails loudly with instructions if the folder is missing.
- The worker loads with `indexURL: "/pyodide/"`. At runtime **nothing is downloaded**.
- **Known cost:** Tauri embeds `public/` into the executable, so exe size and compile time grow. If the embed step becomes unreasonable (a build noticeably over about 5 minutes, or an exe over about 250 MB), the fallback is shipping the folder as a Tauri `resource` served via the asset protocol. That would be a separate decision to raise with the user, because it touches the CSP and asset scope.

### CSP change (user-approved; the only one)

`tauri.conf.json` gains `script-src 'self' 'wasm-unsafe-eval'`, keeping everything else identical. `worker-src` falls back to `script-src`.

**Stop-and-ask rule:** if Pyodide also needs `'unsafe-eval'` (or anything else), the implementer must stop and ask the user, never widening it silently.

## Datasets (licence-clean)

- **Synthetic "Bharat Retail"** company data, generated by a seeded, deterministic `scripts/generate-practice-datasets.mjs`. The output is committed as CSVs (small, a few hundred KB total).
  - Tables: `customers`, `products`, `orders`, `order_items`, `employees`, `regions`, `monthly_sales`.
  - Includes realistic Indian cities/states, INR prices and dates spanning about 2 years.
  - Nulls and a few messy values are deliberately included so cleaning exercises are possible.
- **Iris** (public domain, 150 rows).
- **Palmer Penguins** (CC0; credit Horst, Hill & Gorman).
- All tables load into SQLite and are available as pandas DataFrames.
- A small "Datasets" panel shows each table's columns and first rows.

## Lessons (original writing)

**Lesson shape** (W3Schools/GfG style):
- a short explanation;
- one worked example with a **Try it** editor, pre-filled and runnable;
- 2–3 **exercises** that are auto-checked.

**Checking**, in a pure `practice/check.ts`:
- **SQL:** run the user's query and a hidden reference query, then compare result sets. Column names are case-insensitive, numbers are rounded to 6 decimal places, rows are compared as a multiset unless the exercise sets `ordered: true`.
- **Python:** run the user's code, then hidden `assert` lines. Pass means no exception.
- **Feedback:** "Correct", or a concise diff (missing/extra rows, first mismatch, or the failing assertion's message).

**Curriculum:**
- **SQL, about 14 lessons:** SELECT; WHERE; ORDER BY/LIMIT; aggregates; GROUP BY/HAVING; INNER/LEFT joins; multi-table joins; subqueries; CTEs; CASE; string & date functions; window functions (ROW_NUMBER/RANK/LAG, running totals); NULL handling; interview patterns (top-N per group, second-highest, YoY growth, retention).
- **Python, about 18 lessons:**
  - core language: types, lists/dicts, loops, functions, comprehensions, errors;
  - pandas: load/inspect, filter, groupby/agg, merge, pivot, dates, cleaning;
  - visualisation: matplotlib basics, seaborn;
  - scikit-learn: train/test split + linear regression, classification + metrics;
  - scipy: t-test/correlation.
- Content is typed TS data in `apps/desktop/src/practice/content/{sql,python}/*.ts`.

## UI

- **Layout:** Practice view, left list of tracks → lessons with ✓ progress; right lesson pane.
- **Editor:** a monospace `<textarea>` (Tab inserts 4 spaces, Ctrl+Enter runs). No new editor dependency.
- **Output area:**
  - tables for SQL results and DataFrames (the first 200 rows, with a row count);
  - text for stdout/stderr and tracebacks;
  - an image for matplotlib/seaborn charts. The worker renders to PNG and posts a `data:` URL, which the existing `img-src data:` allows.
- **Buttons:** Run · Stop · Reset code · Show solution (only after one attempt).

## Storage

## Testing

- **vitest** for `check.ts`: equal sets in a different order; an ordered mismatch; a float tolerance case; a column-name case difference; missing/extra rows; a Python assertion failure message.
- **CDP (live):**
  - With the network disabled (DevTools `Network.emulateNetworkConditions offline`):
    - the worker boots;
    - `SELECT count(*) FROM orders` returns;
    - `import pandas, numpy, matplotlib, sklearn, seaborn, scipy` succeeds.
  - `while True: pass` followed by Stop returns control within 1 s.
  - Inside the worker, `typeof self.__TAURI_INTERNALS__` is `"undefined"`.
  - A seaborn chart renders as an image.
  - A lesson exercise passes with the right answer and fails with a helpful diff.
- The CSP diff is exactly the one added directive.
